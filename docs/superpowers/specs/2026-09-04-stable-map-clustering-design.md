# Стабильная дифференциальная кластеризация карты

## Цель

Устранить заметное моргание маркеров при масштабировании или прокрутке карты. Маркеры и группы, сохраняющие ту же логическую идентичность, должны сохранять тот же объект Yandex MapKit `PlacemarkMapObject`. Обновлять, добавлять или удалять можно только сущности, у которых изменились состав, представление или видимость.

Существующий буфер запроса в 20% вокруг видимой области карты остаётся без изменений.

## Текущая причина

`CameraMarkerDiff` сохраняет записи отдельных камер, но каждое изменение всё равно вызывает `ClusterizedPlacemarkCollection.clusterPlacemarks()`. MapKit перестраивает внешний вид групп для всей коллекции, поэтому неизменившиеся одиночные и групповые иконки заметно исчезают и появляются снова.

## Модель кластеризации

Заменить `ClusterizedPlacemarkCollection` на постоянную обычную `MapObjectCollection`.

При масштабе ниже 14 камеры распределяются по детерминированной сетке Web Mercator. Уровень сетки равен целой части текущего масштаба, а размер ячейки соответствует существующему радиусу кластеризации 52 пикселя. Координаты сетки привязаны к мировому пространству, а не к экрану, поэтому прокрутка не меняет состав групп.

При масштабе 14 и выше каждая камера представлена отдельно.

Одиночная сущность имеет стабильный ключ `camera:<camera-id>`. Сущность группы имеет стабильный ключ `cluster:<zoom-level>:<cell-x>:<cell-y>`. Перед вычислением сигнатур участники группы сортируются по идентификатору камеры. Позиция группы является географическим центроидом текущих участников.

## Дифференциальная отрисовка

Этап компоновки создаёт неизменяемые сущности отрисовки, содержащие:

- стабильный ключ;
- вид: одиночный объект или группа;
- позицию;
- идентификаторы участников;
- сигнатуру представления;
- данные камеры для одиночной сущности.

Этап diff сравнивает требуемые сущности с уже отрисованными:

- одинаковые ключ и сигнатура: не выполнять вызовов MapKit;
- тот же ключ при изменившемся составе группы: обновить только геометрию и иконку группы этого маркера;
- новый ключ: добавить один маркер;
- отсутствующий ключ: удалить один маркер;
- изменение представления одиночного объекта: по возможности обновить этот маркер на месте.

Несвязанные группы и одиночные маркеры не должны получать вызовы `setIcon`, `setGeometry`, удаления или добавления.

Полигоны областей действия остаются в существующей отдельной дифференциальной коллекции по камерам. Маркер текущего GPS-положения остаётся независимым от маркеров камер.

## Поток данных

1. Завершённое перемещение камеры Яндекс-карты запрашивает камеры из SQLite с использованием текущих границ с буфером.
2. Существующий счётчик поколений отбрасывает устаревшие результаты асинхронных запросов.
3. Чистый компонент компоновки создаёт стабильные одиночные и групповые сущности для текущего масштаба.
4. Чистый компонент diff сообщает о добавлениях, удалениях, обновлениях на месте и неизменившихся сущностях.
5. `MainActivity` применяет только эти операции к постоянной обычной коллекции MapKit.

Когда новая камера присоединяется к существующей видимой группе, разрешено обновить количество и позицию этой группы. Все несвязанные видимые сущности остаются без изменений.

## История версий

Версия `4.9.3` будет содержать собственное видимое описание изменений в окне «О программе». Версия `4.9.2` также будет добавлена в известную историю версий. Окно покажет описание текущей версии непосредственно под её номером, а ниже перечислит старые версии без дублирования текущей записи.

## Обработка ошибок

Пустой результат запроса удаляет только сущности, которых больше нет в области с буфером. Устаревший результат запроса не приводит к отрисовке. Компонент компоновки пропускает некорректные координаты камер вместо создания недопустимых координат Mercator.

## Тесты

Чистые JVM-тесты проверят:

- прокрутка при том же масштабе сохраняет ключи групп;
- добавление камеры в одну группу изменяет только эту группу;
- несвязанная группа остаётся в diff без побайтовых изменений;
- при масштабе 14 создаются сущности отдельных камер;
- изменившийся одиночный объект обновляется без принудительной замены несвязанных объектов;
- история версий содержит текущую версию и непустое описание.

Релизная сборка Android и smoke-тест на установленном устройстве проверят холодный запуск, повторяющиеся операции масштабирования и прокрутки, содержимое окна «О программе» и отсутствие ошибок `AndroidRuntime`.
